# K5 AOT, Cache, And SDK

Status: cache, predecoded execution, SDK, packaging, and reference bindings are complete.
The AOT backend supports numeric/Trit arithmetic, branches, loops, internal calls, and
numeric structured exceptions; FFI and containers remain unsupported native-backend paths.

K5 keeps Dao Binary Module v1 stable. VM ABI v9 records the audited container-handle,
index-mutation, list-append, local function-reference, and same-call binding semantics;
cache, SDK, and AOT layers do not reinterpret module fields.
The VM's string-keyed Map `INDEX_GET` returns `null` for a missing key, preserving the
legacy Ku and C-VM parity contract without adding a new module opcode. The host inspection
API continues to return `DAO_EXPORT_NOT_FOUND` so callers can distinguish key absence.

## Verified Module Cache

Each VM caches up to 64 verified modules by default. Cache lookup
uses the module fingerprint followed by full byte equality, so hash collisions cannot
substitute a different module. Modules are reference-counted: clearing or destroying a
VM releases its cache references without invalidating caller-owned references.

`dao_vm_get_cache_stats` reports entries, hits, and misses. Use
`dao_vm_set_module_cache_capacity` to configure capacity or disable caching.

Functions retain direct pointers to their decoded instruction arrays after verification;
the interpreter does not decode instruction bytes or recompute function code offsets on
the hot path.

## AOT Backend

`dao-aot input.dao output.c` accepts a verified module containing numeric and Trit
functions. The generated portable C preserves argument checks, integer overflow,
division/remainder traps, comparisons, return behavior, and function-local exception
handlers with cross-function propagation. Unsupported opcodes fail the translation rather
than falling back silently.

On Windows, `tools/aot_kernel.ps1` generates C and compiles it to a native DLL with the
managed Clang toolchain. CTest compiles, dynamically loads, executes, and benchmarks the
native result. The performance gate requires at least 0.8x of an equivalent checked
native function across the same DLL boundary. The gate uses seven interleaved samples
and compares medians.

The performance suite includes scalar addition and a checked numeric loop against native
baselines across the same DLL boundary.

## SDK And Bindings

`tools/package_kernel.ps1` builds, tests, installs, and creates
`DaoKernel-0.2.0-<platform>.zip`. The SDK contains:

- runtime DLL/import library and static C++ tool libraries;
- public C/C++ headers and CMake package exports under the `Dao::` namespace;
- `dao-ku` and `dao-aot` tools;
- Python `ctypes` and Rust `dao-kernel-sys` reference bindings;
- format, FFI, and runtime documentation.
