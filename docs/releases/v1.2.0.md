# Ku v1.2.0 — Windows x64 Alpha

2026-11-23。此次先发布 **Windows x64 SDK**；Linux/macOS 附件留待对应验证后提供。

## 下载与快速验证

下载 `Ku-1.2.0-Windows-AMD64.zip` 及同名 `.zip.sha256`。PowerShell 校验：

```powershell
Get-FileHash .\Ku-1.2.0-Windows-AMD64.zip -Algorithm SHA256
```

解压后，在 SDK 根目录运行：

```powershell
.\bin\dao-ku.exe --test share/dao/examples/record_tests.ku
.\bin\dao-ku.exe --test share/dao/examples/config_validator_tests.ku
.\bin\ku-config.exe share/dao/examples/service.conf
```

SDK 附带所需 LLVM C++ 动态库和许可。运行原生工具不需要 Python；Python/Rust 绑定按各自宿主环境使用。

## 新增与修复

- `dao-ku --test` 原生测试发现与执行，支持中文 `测试_` 和英文 `test_`。
- 编译错误包含原始文件、行列及源码指示，源码导入后仍定位回原文件。
- 只读标量 Record：中文 `型`、具名构造、字段读取、List/Map 嵌入、严格字段检查。
- v3/ABI11 的 loader/verifier、VM、C ABI、汇编往返、显式 Store 能力策略和 Python/Rust 只读查询。
- 原生 `ku-config`：规则在 Ku 中执行，内部使用 Record，公开 Map/CLI 输出保持兼容。
- 修复源码兄弟导入误判循环、导入字段名错误改写，以及 `keys(Map)` 和相似函数名误识别。

## 能力与兼容性

普通模块保留 v1/ABI9、v2/ABI10 路径。Record 模块使用 v3/ABI11，通用 VM 默认关闭该能力；
嵌入方须显式启用 `DAO_FEATURE_RECORDS`，Store/CodeMemory CLI 使用 `--enable-records`。
运行时 Record 句柄仍受 VM generation 限制，不跨调用复用，也不持久化为值。
Record 及含 Record 的容器不能穿越 Host/独立模块边界。数值 AOT 在打开输出前拒绝全部 v3 模块。

SDK、Python 项目和 Rust 绑定版本统一为 `1.2.0`；标准库模块 identity 的版本仍为 `1.0.0`。
Schema、Result/Option、嵌套 Record、完整 Typed IR、跨模块类型签名和自主规划仍未交付。

## 验证范围

- Windows 功能 CTest、自举 B0=B1=B2、双前端字节一致、Python 集成测试。
- 解压后的 SDK 在移除开发搜索路径的环境验证原生工具、Store、配置示例与绑定。
- 开发阶段 Record 内核/工具/Store/配置 CLI 的独立 ASan/UBSan 检查通过。
- 独立 AOT 性能阈值、全量旧链、fuzz/soak、断电持久性及本版本 Linux/macOS 发行验证不在此次发布范围。

完整逐项说明见 `share/doc/dao_kernel/KU_RECORD_R1_ACCEPTANCE.md` 与 `KU_RECORD_BINDINGS.md`。
