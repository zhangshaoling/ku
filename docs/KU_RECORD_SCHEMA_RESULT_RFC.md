# RFC：Record / Schema / Result 最小契约

> 日期：2026-11-22
> 状态：语言提案；Record 内核与双前端源码切片已实现，Schema 与 Result/Option 尚未实现，不覆盖当前 Ku v1 语义。实现范围见 [RECORDS.md](../kernel/RECORDS.md)。
> 目标：为结构化值确定边界，并给出下一张可执行工作单。

## 1. 当前依据与前提

- [Ku v1 语义](KU_V1_SEMANTICS.md)：Map 可变，缺失键返回 `空`；`object.field` 当前为字符串键访问语法糖。
- [值所有权](../kernel/OWNERSHIP.md)：容器属于一次顶层调用的 generation，字符串/字节仍为借用；容器不能作为下一次顶层调用的参数。
- [模块 ABI](../kernel/MODULE_ABI.md)：按 identity/精确版本链接，目前只校验导出符号和参数个数，没有字段或函数值类型签名。
- [二进制格式](../kernel/FORMAT.md)：默认接受 v1/ABI9、v2/ABI10；新内核 opt-in 支持 v3/ABI11，拒绝未知 section/opcode。
- [配置校验器](KU_CONFIG_EXAMPLE.md)：现用 `{ok, errors}` Map 表达结果，错误项为 `{line, key, code, message}`，规则由 Ku 执行。

本提案假定继续保持中文规范语法、模型无关、双前端确定性和显式 Host 边界。
Schema 表达值的结构；端口范围、来源可信度等业务或证据判断仍由普通程序完成。

## 2. 选择与替代方案

| 问题 | 建议选择 | 替代方案及暂不选择的原因 |
|---|---|---|
| Record 是否独立 | 独立名义类型和运行时值标签 | 仅把 Map 改名无法保证身份、字段集合和写入规则；可作显式适配，不能冒充 Record |
| 类型判等 | 按声明身份，字段相同也不自动互换 | 结构兼容推导扩大跨模块兼容和类型推导范围 |
| 字段 | 固定、必填、构造后只读 | 默认值、隐式缺省和可变字段增加初始化与别名语义 |
| 缺失/多余字段 | 拒绝构造；错误字段读取报错 | 返回 `空` 会继续掩盖拼写错误；忽略多余字段会掩盖版本不匹配 |
| Map 转换 | 显式校验并构造 | 隐式转换会使普通数据读取具有隐藏的失败和分配行为 |
| 生命周期 | 延续 generation arena | 引入 GC、retain 或跨调用共享不是本切片的必要条件 |
| 首次实现范围 | 同模块、标量字段；其余分批 | 一次加入泛型、动态 Schema、模型接口和持久化会扩大验证范围 |

以下条目是建议冻结的语义；具体二进制编号与 C 函数签名见 [R0 候选附录](KU_RECORD_R0_ABI.md)。它们仍是提案，发布版本未定。

## 3. Record 源语言与值

以下 Record 语法已接入当前开发中的两套源码前端；Schema/Result 仍为提案：

```ku
型 校验错误 {
  行号: 整数
  字段: 文本
  代码: 文本
  消息: 文本
}

思 构造错误() {
  返 校验错误 {
    行号: 2,
    字段: "port",
    代码: "range",
    消息: "port must be a decimal integer in 1..65535"
  }
}
```

### 声明与构造

1. 类型声明位于模块顶层；字段名不得重复。R1 字段类型限 `整数/i64`、`三值/Trit`、`文本/String`、`字节/Bytes`，无隐式转换。
2. `型` 为顶层声明位置的上下文关键字；既有 `思 型()`、同名变量和 Map 字段不能因新关键字被全局禁用。
3. 类型、顶层函数和 Host 导入共享声明名冲突检查。引入类型的模块中，局部变量或参数不得遮蔽可见类型名，避免 `名称 { ... }` 被误读为普通块。
4. 类型声明可以前向引用；字段的缺失、多余、重复与确定的类型错误在编译期拒绝。无法静态确定的字段值在构造时严格检查，失败产生类型错误，不能发布半构造对象。
5. 构造字段可按任意顺序书写；表达式严格按书写顺序求值一次，再按声明顺序放入槽位。相同输入在两套前端必须生成相同字节；不要求重排表达式后的源码产生相同字节。
6. 字段无默认值、无可空缩写、无隐式补 `空`。`整数` 不接受 Trit `+1`，文本不接受 Bytes。

### 读取、修改与容器

- `记录.字段` 读取固定字段。已知类型上的未知字段是编译错误；动态路径遇到错误类型或不存在字段时为类型错误。
- `记录["字段"]`、字段赋值、动态增删、`keys(记录)`、`len(记录)` 均不在本提案的 Record 接口内；不得转而按 Map 执行。
- 复制 Record 值只复制句柄；字段只读，不发生隐式深复制。R1 标量字段不会引入可变子容器。
- 只读指字段绑定，不能据此宣称借用的 String/Bytes 底层存储已冻结或已归 VM 所有；其 owner 仍须保持内容与有效性契约。
- Record 可以作为 List 项或 Map 值，与其他合法值混放；不能作为 Map 键。`List`、`Map` 继续保持原有动态和值可变规则。
- R1 不支持 Record 深相等或引用身份比较；`==/!=` 对两个 Record 报类型错误。与其他类型的判等仍按现有跨类型规则，结果不相等。
- 后续 R2 允许字段引用同模块其他 Record，但声明依赖须为无环图。第一阶段不加入递归类型、List/Map 字段或任意对象字段。

普通 Map 的缺失值行为保持不变。Record 模块需保留独立的字段访问 AST，不能把所有字段访问提前丢失为 `INDEX_GET`：
已知 Record 可降为槽位读取；未定类型的点访问需在新模块协议中检查 Map/Record，方括号访问继续拒绝 Record。
不含新语义的旧源码继续走旧格式和既有 lowering，不为了接入 Record 重写所有程序。

### 声明身份

- 本地类型由拥有它的不可变模块及声明索引确定，短名称或相同字段形状均不足以判等。
- 源码组合沿用别名限定，并重写类型声明和引用，避免依赖中的同名类型合并；两个不同别名的源码组合实例视为不同声明。
- 独立模块之间的公开类型身份为 `(模块 identity, 精确版本, 类型声明名)`；只在类型描述与已链接模块验证一致后建立对应关系。
- 未标识模块可持有本地 Record，但不能把本地声明作为独立模块的公开类型导出。
- 内容指纹仍只是缓存提示，不作为类型或 Schema 的可信身份。

## 4. Schema 与转换

Schema 是由 Record 声明导出的确定性结构描述，不是任意运行时代码、JSON Schema 全集或数据库表定义。
最小描述包含类型身份、按声明顺序排列的字段名称及精确字段类型；R2 加入嵌套类型引用。

建议的转换契约（下列名称为抽象操作，**不是现有 CLI 或内建函数**）：

| 操作 | 结果 | 规则 |
|---|---|---|
| `validate(T, Map)` | 错误列表 | 检查字段集合及严格类型，不改变输入，不分配可见 Record |
| `from_map(T, Map)` | `Result<T, List<结构错误>>` | 通过全部检查后构造；缺失和未知字段均报错 |
| `to_map(Record)` | 新 Map | 字段集合与声明相同；调用者修改该 Map 不影响 Record |

这些操作在 Schema/Result 阶段交付，R1 不提供占位实现。
结构错误至少包含字段路径、错误码、期望类型和实际类型；缺失字段的实际类型为明确的“缺失”，与 `空` 区分。
错误顺序固定为：按声明顺序报告缺失/类型错误，再按 UTF-8 字节序报告未知键；同一字段不重复生成类型错误。
R2 的转换递归构造/导出嵌套 Record；Map 中其他可变值不属于初始可转换字段集合，不承诺任意图的深复制。

`port: 整数` 只证明值为 i64。`1 <= port <= 65535` 仍由普通 Ku 校验函数实现；
若未来引入范围约束，应另行定义可序列化约束语言与执行预算，不能将任意回调塞入 Schema。

## 5. Result / Option 的行为契约

本节使用 `Result<T,E>`、`Option<T>`、`Ok/Err`、`Some/None` 作为**设计记号**；
中文构造语法、泛型声明、分支绑定语法在后续专门切片冻结，本 RFC 不预留这些普通函数名。

| 类型 | 合法状态 | 读取规则 |
|---|---|---|
| `Result<T,E>` | 恰为 `Ok(T)` 或 `Err(E)` | 只允许读取当前分支的载荷；分支错误是类型错误，不能返回 `空` |
| `Option<T>` | 恰为 `Some(T)` 或 `None` | 缺省是一种独立状态；`None` 不等于 `空`、假或空字符串 |

- Result 和 Option 是带标签的和类型，不是具有 `ok/value/error` 可变字段的 Map；不能同时拥有成功和失败载荷。
- 普通调用、`返`、List/Map 容器可以传递它们；生命周期与 Record 一致，嵌套载荷必须满足相同边界检查。
- 不隐式解包、不自动抛出、不把 VM 类型错误/预算耗尽改成业务 Err。错误传播运算符与完整模式匹配不属于首次实现。
- 在完整静态类型与模式检查落地前，标签与载荷访问仍需运行时检查；不能宣称已静态证明错误均被处理。
- `试/捕` 保持仅捕获显式 `抛` 的现有契约。现有 `std/error` Map 约定继续可用，通过显式适配迁移。

## 6. 生命周期、Host 与模块边界

Record/Result/Option 的 payload 使用 VM generation 句柄，不存进程指针；`dao_value` 的 16 字节布局保持目标不变。
复制句柄不延长生命周期；下一次已接受顶层调用、VM 销毁或跨 VM 使用的拒绝规则与 List/Map 一致。
返回的嵌套 String/Bytes 仍是借用；记录本身不能让 Host 栈内存或已释放输入重新有效。

新增字段检查还必须满足：

- R1 只在同一模块执行中创建、传递、读取；允许支持新协议的 Host 在本次调用结束后、下次调用前检查返回 Record。
- Record 类型描述由拥有模块维护。arena 中引用描述的模块必须被保活至该 generation 清理，即使调用者先 release 模块或清空缓存也不能悬空。
- 顶层传入 VM Record 句柄仍被拒绝；Host 构造只允许在已注册回调期间进行，且必须指定已验证的类型描述并一次性校验全部字段。
- R1 不提供 Host 构造、Record 载荷的 Host 参数/返回值或独立模块传递；新标签藏在 List/Map 中也要递归拒绝。只有顶层返回值的只读检查属于 R1。
- R2 之后解锁这些边界时，检查须覆盖所有嵌套 Record、Result、Option 和现有容器；Function/Closure 的禁止规则不得被新包装绕过。
- 独立模块要同时拥有已链接的类型描述及匹配的参数/结果类型签名；仅 arity 相同不能接受 Record。签名协议落地前明确拒绝，不能临时按 Map 放行。
- 旧 Host/旧模块不能因升级内核就自动收到新值标签；需要显式的新值能力协商。新 VM 的默认旧能力范围保持可用，新协议加载需调用者选择启用；不复用当前必须为零的 reserved 字段。

上述能力协商的具体新增 C API 和只读字段查询函数由 R0 冻结。可加新函数，但不能扩大旧函数接受的标签而不说明调用者的兼容条件。

## 7. 编码、版本与持久化

本提案要求新的模块/VM 协议版本承载类型描述、Record 指令及后续类型签名；
不能在 v2/ABI10 内偷加 section、把新标签编码为 Map，或改变既有指令意义。
版本、opcode、值标签和 section ID 集中定义在 [R0 附录](KU_RECORD_R0_ABI.md)；新内核已 opt-in 支持，两套源码前端已接入。

R0 编码附录已给出候选字节布局、尺寸限制、确定性排序和反例，供后续 R1 实现与验证。
旧加载器必须明确拒绝新版本；新加载器继续接受原有合法版本。无新语义的模块应保留现有产物与门禁。

Verifier 至少验证：描述引用/边界、重复名、合法字段类型、构造数量、字段槽位及指令操作数；
动态字段值类型由构造/读取路径继续验证。模块验证成功不等于 Schema 业务规则或知识结论正确。

类型版本随所属模块精确版本变化。增加、删改、重排字段都视为类型契约变更，需新模块版本；
没有“新增可选字段自然向后兼容”的隐式规则，也不提供版本范围协商。

ModuleStore 当前保存模块字节，不保存任意运行值。本切片不把 Record 句柄持久化，
不调整 schema-1 manifest，也不把该 manifest 与本 RFC 的 Schema 混为一谈。
持久化值需要单独定义 `(类型身份, 字段数据)` 的版本化编码和显式迁移；不序列化内存地址或 generation。

## 8. 用配置校验器检验设计

当前实际接口继续为 `校验(文本) -> {ok, errors}`；本 RFC 不改动工具或 SDK 的返回格式。
迁移按下列顺序进行；当前错误 Record 与显式 Map 导出已落地，其余仍待后续阶段：

| 当前内容 | 目标 | 所需阶段 |
|---|---|---|
| 错误项 `{line,key,code,message}` | 固定 `校验错误` Record | R1：四个标量字段，直接可检验 |
| `name/port/workers` 的有效配置 | `配置` Record，worker 缺省由业务显式补值 | R1：标量字段；不把源文本的省略等同于 Record 缺字段 |
| 错误列表 | `List<校验错误>` 的静态描述 | 后续容器类型与 Typed IR；动态 List 容纳 Record 本身可在 R1 使用 |
| `{ok, errors}` | `Result<配置, List<校验错误>>` | Result 阶段；成功返回实际配置，失败返回非空业务错误列表 |
| 缺失可选配置 | 解析阶段的 Option 或显式业务分支 | Option 阶段；不是 Record 自动补 `空` |

R1 已增加 Record 版错误构造与字段读取验收；实际配置校验器内部使用 Record，通过显式适配输出已有 Map，保持原生宿主结果契约。验收证据见 [R1 记录](KU_RECORD_R1_ACCEPTANCE.md)。
当前工具只返回校验结果，并未返回解析后的配置；将来返回 `配置` 前还需显式决定 worker 缺省策略、解析数值并补齐测试，不能凭结构校验成功伪造配置值。
新增公开类型或改变公开函数返回值时必须单独版本化，不能直接替换已有 CLI 内部结果而跳过 Host 适配测试。
端口范围、重复键和行号仍由现有 Ku 代码负责；结构类型不能消除这些业务规则。

## 9. 实施顺序与下一张工作单

### R0：编码与能力协商附录（候选设计已完成）

交付见 [KU_RECORD_R0_ABI.md](KU_RECORD_R0_ABI.md)；文档与样本完成，不等于提案已实现。

交付：新模块/值协议的具体布局，Record 构造与字段读取指令，模块保活方案，
只读 Record 检查及能力启用的 C API，旧模块/Host 的递归拒绝规则。
逐项核对 `format.hpp`、loader/verifier、ModuleBuilder、汇编/反汇编、AOT、Python/Rust 绑定和 SDK 入口。
数值 AOT 不支持新值时须在生成前拒绝，并保留旧数值路径。

完成条件：布局无未分配项；新旧支持矩阵明确；类型/指令的合法与恶意字节样本可逐条判定；
双前端生成规则一致。它仍是设计交付，不表示代码实现完成。

### R1：同模块标量 Record 的完整执行切片

实现顶层类型声明、具名构造、字段读取、字段只读检查、List/Map 嵌入、只读 C 检查与新协议。
先完成 AST/最小类型描述，不借机实现完整 Typed IR；在已有信息上做静态检查，其余严格动态检查。
恢复与自举编译器都实现后才开放生产入口，不增加自动 recovery fallback。

### R2 及后续

依次推进无环嵌套 Record、Schema 转换、模块类型签名与 Host 构造，再实现 Result/Option。
容器泛型、模式匹配、约束 Schema、持久值编码和模型输出适配各自有独立验收，不并入 R1。

## 10. 验收清单

以下保留完整语言里程碑的验收要求。当前同模块标量 Record 的 REC-01 至 REC-13、REG-01
已有 Windows 执行证据，逐项见 [R1 验收记录](KU_RECORD_R1_ACCEPTANCE.md)；
SCH/RES 项、跨平台与正式发行验收仍未完成，实现范围见 [RECORDS.md](../kernel/RECORDS.md)：

| ID | 场景 | 预期 |
|---|---|---|
| REC-01 | 中文类型/字段、合法具名构造 | 读取原值；双前端字节一致 |
| REC-02 | 重复字段声明或构造项 | 定位至重复字段并拒绝 |
| REC-03 | 缺失或多余构造字段 | 拒绝，不能默认为空或忽略 |
| REC-04 | i64 字段传入 Trit/文本 | 静态确定时编译拒绝，否则构造时类型错误 |
| REC-05 | 构造项含有副作用且顺序不同 | 按源码顺序各求值一次，槽位仍按声明顺序 |
| REC-06 | Record 未知字段、赋值、动态索引 | 明确拒绝；普通 Map 缺失键仍返回空 |
| REC-07 | 相同字段的两个不同声明 | 不隐式互换；Record 深相等不开放 |
| REC-08 | Record 放入 List/Map 后读取 | 同 generation 内正确，保持只读字段 |
| REC-09 | 下一次调用、跨 VM、release 模块后检查 | stale/foreign 拒绝；有效 arena 的描述保持存活 |
| REC-10 | 旧 Host/模块收到嵌套 Record | 即使藏在容器中也拒绝 |
| REC-11 | 非法类型描述、槽位、数量、未知协议 | loader/verifier 拒绝，无越界或静默降级 |
